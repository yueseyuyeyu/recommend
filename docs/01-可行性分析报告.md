## 1. 引言

### 1.1 编写目的

本报告从技术、经济、操作、法律四个维度论证「商品推荐系统」项目的可行性，
明确项目建设目标、约束条件与风险，为后续需求分析、系统设计与编码实施提供决策依据。
本报告面向项目开发者本人及项目评审人员。

### 1.2 项目背景

在电子商务场景下，商品数量与用户数量的快速增长导致「信息过载」，
用户难以在海量商品中快速找到自身需要的物品，商家也难以将长尾商品有效曝光。
个性化推荐系统是解决该问题的主流技术手段。

本项目作为软件工程专业的个人毕业项目，目标是从零构建一套
**具备完整软件工程过程文档、分层清晰、可测试、可部署**的个性化商品推荐系统，
并在工程规范性上全面超越传统的课程设计项目（如基于 Swing + JDBC 的单机管理系统）。

### 1.3 术语说明

| 术语         | 说明                                                              |
| ------------ | ----------------------------------------------------------------- |
| UserCF       | User-based Collaborative Filtering，基于用户的协同过滤            |
| ItemCF       | Item-based Collaborative Filtering，基于物品的协同过滤            |
| 冷启动       | 新用户或新商品因缺乏历史行为数据而无法被个性化推荐的场景          |
| 余弦相似度   | 用两个向量夹角余弦值衡量相似度，本项目用于计算用户/物品相似程度   |
| 召回         | 从候选集中快速筛出一小批可能感兴趣的商品的过程                    |
| Top-N 推荐   | 向用户返回一个长度为 N 的有序推荐列表                             |

## 2. 可行性分析

### 2.1 技术可行性

#### 2.1.1 技术选型与成熟度

| 层次     | 技术选型                            | 成熟度                                   | 评估 |
| -------- | ----------------------------------- | ---------------------------------------- | ---- |
| 后端框架 | Spring Boot 3.x                     | 业界事实标准，社区活跃，长期支持         | 可行 |
| 持久层   | MyBatis-Plus + HikariCP             | 成熟 ORM 增强框架，连接池为 Spring Boot 默认 | 可行 |
| 数据库   | MySQL 8.0                           | 本机已安装（8.0.27），广泛支持           | 可行 |
| 前端     | Vue 3 + Element Plus + Vite         | 主流前端组合，组件库完善                 | 可行 |
| 构建     | Maven + Maven Wrapper               | 无需预装 Maven，跨平台一致               | 可行 |
| 测试     | JUnit 5 + Mockito                   | Java 生态标准测试框架                    | 可行 |
| 鉴权     | Spring Security + JWT + BCrypt      | 成熟方案，文档充分                       | 可行 |

#### 2.1.2 核心算法可行性

推荐算法采用 UserCF 与 ItemCF 双引擎，均基于**余弦相似度**，属于经典的
邻域协同过滤方法，不依赖机器学习框架、不需要 GPU、不需要训练过程，
可在纯 Java 环境下以内存计算完成。

技术要点及可行性判断：

- **相似度计算**：对物品-用户倒排索引求两两共现，时间复杂度约 O(N²)，
  在 500 商品 × 5000 行为的数据规模下可在秒级完成，可接受。
  后续可通过增量更新与缓存优化扩展至更大规模。**可行**
- **冷启动处理**：新用户无行为时无法计算相似度，采用「热门商品 + 新品」兜底策略，
  这是工业界通行做法。**可行**
- **效果验证**：采用离线指标（准确率 Precision、召回率 Recall、F1、覆盖率 Coverage）
  通过留出测试集进行评估，无需线上 A/B 实验即可验证算法有效性。**可行**

#### 2.1.3 技术风险与对策

| 风险                             | 影响 | 对策                                                    |
| -------------------------------- | ---- | ------------------------------------------------------- |
| 本机为 Java 8，Spring Boot 3 需 JDK 17 | 中   | 安装 Temurin JDK 17，项目内声明 `java.version=17`       |
| 相似度计算随数据量平方级增长     | 中   | 限制候选集规模、Top-K 截断、定时任务异步离线计算并缓存  |
| 前后端联调跨域问题               | 低   | 后端配置 CORS，前端 Vite 配置代理                       |
| 无 Docker 环境                   | 低   | 提供本地直接启动方案；Docker 配置作为可选增强项提供     |

**结论：技术可行性成立。**

| 成本项     | 明细                                                        | 成本     |

| 开发工具   | IntelliJ IDEA / VS Code 社区版、Git、Node.js                | 0 元     |

**结论：经济可行性成立。**

### 2.3 操作可行性

- **用户界面**：B/S 架构，用户使用浏览器即可访问，无需安装客户端，
  相较原课程设计的单机桌面程序显著降低了使用门槛。
- **部署运维**：提供 `docker-compose` 一键启动与本地启动两种方式，
  配套部署手册与初始化 SQL 脚本，具备基本的计算机操作能力即可完成部署。
- **数据初始化**：提供种子数据生成器，一键生成可复现的演示数据，
  避免手工录入，降低环境准备成本。
- **可维护性**：采用分层架构与统一响应体，模块职责清晰，
  配合单元测试与接口文档，后续维护与扩展成本低。

**结论：操作可行性成立。**

### 2.4 法律可行性

- 全部软件依赖均为开源许可（Apache-2.0、MIT 等），商业友好，无授权风险。
- 商品与用户数据由程序生成的**模拟数据**构成，不涉及真实个人信息，
  不触及《个人信息保护法》相关问题。
- 系统在设计中遵循密码加密存储、参数化查询防注入等安全规范，
  符合《网络安全法》对信息系统安全的基本要求。
- 系统不提供第三方支付、不采集真实用户隐私数据，无合规风险。

**结论：法律可行性成立。**

## 3. 与参考项目的对比论证

参考项目为「房屋租赁信息系统」（Java Swing + JDBC，4839 行，零测试，无版本控制）。
本项目的改进必要性论证如下：

| 对比维度     | 参考项目               | 本项目                              | 改进必要性                         |
| ------------ | ---------------------- | ----------------------------------- | ---------------------------------- |
| 架构形态     | C/S 单机桌面           | B/S 前后端分离                      | 桌面程序无法多人访问，已不符合主流 |
| 连接管理     | 每次新建，从不关 Statement | HikariCP 连接池 + 框架托管      | 原实现存在资源泄漏，属严重缺陷     |
| 密码安全     | 明文存储与比对         | BCrypt 加盐 + JWT                   | 明文密码属高危安全问题             |
| SQL 安全     | 存在字符串拼接         | 全参数化查询                        | 存在注入风险                       |
| 分层         | 界面直接调用 Dao       | Controller→Service→Mapper 四层      | 业务逻辑无法复用与测试             |
| 测试         | 无                     | JUnit 5 全覆盖，交付前全通过        | 无测试无法保证质量                 |
| 构建         | Eclipse 手工配 jar     | Maven + Wrapper                     | 依赖不可复现，换机即失效           |
| 版本控制     | 无                     | Git + Conventional Commits + GitHub | 无法追踪与回滚                     |
| 业务深度     | CRUD 管理信息系统      | 含推荐算法核心                      | 技术含量与区分度显著提升           |

**结论：本项目在参考项目基础上进行了系统性重构与升级，改进必要且方向明确。**

## 4. 结论与建议

### 4.1 可行性结论

技术、经济、操作、法律四个维度的可行性均成立，
**项目可行，建议立项实施**。

### 4.2 实施建议

1. **严格遵循软件工程流程**：依次产出可行性分析 → 需求规格 → 概要设计 →
   详细设计 → 编码 → 测试 → 部署文档，每个阶段产出对应文档并纳入版本控制。
2. **测试驱动核心算法**：推荐算法为核心竞争力，必须编写完整单元测试，
   并输出离线评测指标作为效果证明。
3. **每改动一次即提交一次**：遵循 `AGENTS.md` 约定，保持 commit 粒度清晰，
   确保任意阶段均可回滚。
4. **分阶段推进**：优先打通「数据库 → 后端骨架 → 算法 → 接口」主线，
   再补全前端界面，避免并行推进导致主线断裂。
5. **预留扩展点**：推荐引擎采用策略模式抽象，便于后续接入
   内容推荐、矩阵分解等算法而不改动上层代码。
