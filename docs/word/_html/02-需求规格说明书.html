2. 系统概述

2.1 系统定位

本系统是一套面向电商场景的 B/S 架构个性化商品推荐系统。系统采集用户的 浏览、点击、加购、购买、评分等行为数据，通过基于用户的协同过滤（UserCF） 与基于物品的协同过滤（ItemCF）两种算法生成个性化推荐列表， 并通过 Web 界面提供商品浏览、搜索、购物车、下单与推荐展示能力。

2.2 系统目标

编号 目标
G1 为用户提供个性化商品推荐，降低信息过载下的筛选成本
G2 提供完整的电商基础业务闭环：浏览 → 搜索 → 加购 → 下单 → 评价
G3 实现可解释、可评测的推荐算法，输出准确率/召回率/覆盖率等离线指标
G4 建立分层清晰、可测试、可维护的工程架构，满足软件工程规范性要求
G5 提供完整的过程文档与一键部署能力，保证系统可复现

2.3 用户角色

角色 描述 主要诉求
普通用户 注册登录后可浏览、搜索、购买、评价商品 快速找到感兴趣的商品
管理员 管理商品、类目、订单与用户，查看系统统计 高效维护商品数据，监控系统运行状况
游客 未登录用户 可浏览首页与热门商品，引导其注册

2.4 系统运行环境

类别 要求
服务端 JDK 17+、MySQL 8.0+、内存 ≥ 2GB
客户端 现代浏览器（Chrome / Edge / Firefox 最新版）
网络 支持 HTTP/HTTPS 访问

3.2 功能需求详述

F1 用户与认证模块

F1.1 用户注册

项 说明
功能描述 游客填写用户名、密码、确认密码、邮箱完成注册
输入 用户名、密码、确认密码、邮箱（选填）
处理 1. 校验用户名长度 4–20 位、仅允许字母数字下划线<br>2. 校验密码长度 ≥ 6 位<br>3. 校验两次密码一致<br>4. 校验用户名唯一性<br>5. 密码经 BCrypt 加盐哈希后存储<br>6. 默认分配「普通用户」角色
输出 注册成功返回用户信息；失败返回具体错误原因
异常 用户名已存在 → 提示「用户名已被注册」；参数不合法 → 返回字段级校验错误

F1.2 用户登录

项 说明
功能描述 用户输入用户名与密码完成登录，获取访问令牌
输入 用户名、密码
处理 1. 按用户名查询用户<br>2. BCrypt 校验密码<br>3. 生成 JWT 令牌（有效期 24 小时）<br>4. 记录最后登录时间与 IP
输出 JWT 令牌 + 用户基本信息（不含密码哈希）
异常 用户名不存在或密码错误 → 统一提示「用户名或密码错误」（不区分，防枚举）

F1.3 用户退出：客户端清除令牌，服务端将令牌加入黑名单（可选增强）。

F1.4 个人信息维护：用户可查看与修改昵称、邮箱、头像，修改密码需验证原密码。

F3 行为采集模块

行为数据是推荐算法的输入基础，其权重定义如下：

行为类型 编码 权重 说明
浏览 `VIEW` 1.0 进入商品详情页
点击 `CLICK` 2.0 点击推荐位或列表项
加入购物车 `CART` 3.0 加入购物车
购买 `PURCHASE` 5.0 订单完成
评分 `RATE` 4.0 用户显式打分（1–5 分）
项 说明
功能描述 前端在用户产生交互时异步上报行为，后端持久化到行为表
输入 用户 ID、商品 ID、行为类型、评分值（评分行为时必填）、时间戳
处理 1. 参数校验<br>2. 异步写入数据库（不阻塞主流程）<br>3. 同一用户对同一商品的重复浏览行为更新权重而非无限累加
输出 上报成功（HTTP 200）
约束 行为上报失败不得影响主业务流程

F4 推荐模块 ★核心

F4.1 首页个性化推荐（UserCF）

项 说明
功能描述 为登录用户生成基于用户的协同过滤推荐列表
输入 用户 ID、推荐数量 N（默认 10）
处理 1. 构建「用户-商品」行为矩阵（按行为类型加权）<br>2. 计算目标用户与其他用户的余弦相似度<br>3. 取相似度最高的 K 个邻居（K 默认 20）<br>4. 汇总邻居有过交互而目标用户未交互的商品，按「相似度 × 行为权重」加权打分<br>5. 剔除用户已购买商品，按分数降序取前 N<br>6. 若候选不足，用热门商品补足
输出 有序推荐商品列表（含商品信息 + 推荐分 + 推荐理由）
异常 用户无历史行为 → 触发冷启动，返回热门商品榜单

F4.2 商品详情页相似推荐（ItemCF）

项 说明
功能描述 根据当前商品，推荐与其相似的其他商品
输入 商品 ID、推荐数量 N（默认 6）
处理 1. 构建「商品-用户」倒排索引<br>2. 计算物品间余弦相似度（含热门物品惩罚因子）<br>3. 取相似度最高的 Top-N 个物品<br>4. 剔除当前商品本身与已下架商品
输出 相似商品列表（含相似度分值）
异常 商品无共现数据 → 返回同类目热门商品

F4.3 热门商品推荐：按近 30 天加权行为总量排序取 Top-N，用于首页游客展示与冷启动兜底。

F4.4 猜你喜欢（混合推荐）：将 UserCF 与 ItemCF 结果按可配置权重融合 （默认 UserCF 0.6 / ItemCF 0.4），去重后重排序输出。

F4.5 推荐结果离线评测：按 8:2 划分训练集与测试集， 输出准确率（Precision）、召回率（Recall）、F1 值、覆盖率（Coverage）、 流行度（Popularity）与平均推荐分，用于算法效果验证与展示。

F5 交易模块

F5.1 购物车管理：用户可添加商品、修改数量、删除条目、清空购物车， 购物车数据持久化，登录态下跨设备同步。

F5.2 订单创建：从购物车勾选生成订单，需完成：

  1. 校验库存充足性；2. 校验商品上架状态；3. 扣减库存；
  2. 生成订单号（雪花算法或时间戳+随机数）；5. 记录购买行为用于推荐；
  3. 清空已下单的购物车条目。

以上操作必须在同一事务内完成，任一步失败整体回滚。

F5.3 订单查询：用户按订单状态筛选，分页查看订单列表与订单详情。

F5.4 订单取消：待支付状态下用户可取消订单，取消后回滚库存。

F7 后台管理模块

管理员可对商品、类目、用户、订单执行 CRUD 操作， 并查看系统统计（用户数、商品数、订单数、GMV）与推荐效果监控指标。

需求点 参考项目实现 本项目要求

4.2 安全性需求

编号 需求
S1 用户密码必须使用 BCrypt 加盐哈希存储，禁止明文
S2 所有 SQL 必须使用参数化查询，禁止字符串拼接
S3 接口鉴权基于 JWT，敏感接口校验令牌有效性与角色权限
S4 登录失败提示不区分「用户名不存在」与「密码错误」，防止账号枚举
S5 数据库账号口令不得硬编码，通过配置文件与环境变量注入
S6 敏感操作（下单、改价、删除）须记录操作日志
S7 接口须防重放与越权：用户只能访问自身订单与购物车数据

4.3 可靠性需求

编号 需求
R1 推荐引擎异常时自动降级为热门推荐，不得导致页面不可用
R2 行为上报失败不得阻塞主业务流程
R3 数据库不可用时返回明确错误信息，不抛出堆栈给前端
R4 关键业务（下单）须保证事务一致性，禁止超卖

4.4 易用性需求

编号 需求
U1 页面在 1366×768 及以上分辨率正常显示，响应式适配

数据 规模（种子数据） 说明
用户 200 由种子生成器生成
商品 500 覆盖 10 个一级类目
行为记录 ≥ 5000 保证相似度矩阵有足够的共现数据
订单 ≥ 800 由行为数据派生

5.3 数据约束

  • 用户名唯一且不为空，长度 4–20 位。
  • 商品库存不得为负数，扣减须加行锁或条件更新防超卖。
  • 评分值限定在 1–5 的整数区间。
  • 行为记录的时间不可晚于当前时间。
  • 删除商品采用逻辑删除（`is_deleted` 标记），保留历史订单可追溯性。
