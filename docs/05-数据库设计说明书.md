## 1. 引言

### 1.1 编写目的

本文档定义系统的数据库逻辑结构与物理结构，包含表结构、字段定义、
约束、索引、关系模型及初始化数据方案，作为编码实现与数据库部署的依据。

### 1.2 设计约束

| 编号 | 约束                                                                 |
| ---- | -------------------------------------------------------------------- |
| C1   | 字符集统一 `utf8mb4`，排序规则 `utf8mb4_unicode_ci`                  |
| C2   | 存储引擎统一 InnoDB，支持事务与行级锁                                |
| C3   | 业务数据一律逻辑删除（`is_deleted` 标记），禁止物理删除              |
| C4   | 所有表必含 `create_time`、`update_time` 审计字段                     |
| C5   | 主键统一使用 `BIGINT` 自增，订单号等业务主键单独建立唯一索引         |
| C6   | 金额字段使用 `DECIMAL(10,2)`，禁止使用 `FLOAT`/`DOUBLE`              |
| C7   | 表名避开 MySQL 关键字（订单表命名为 `orders` 而非 `order`）          |

## 2. 概念结构设计

### 2.1 实体清单

| 实体     | 英文名    | 说明                                       |
| -------- | --------- | ------------------------------------------ |
| 用户     | User      | 系统使用者，含普通用户与管理员             |
| 类目     | Category  | 商品分类，支持两级结构                     |
| 商品     | Product   | 被推荐与交易的主体                         |
| 行为     | Behavior  | 用户对商品的交互记录，推荐算法数据源       |
| 购物车   | Cart      | 用户待结算商品集合                         |
| 订单     | Order     | 交易凭证                                   |
| 订单明细 | OrderItem | 订单中的商品条目                           |
| 评价     | Review    | 用户对商品的评分与评论                     |

### 2.2 实体联系

| 联系             | 基数   | 说明                             |
| ---------------- | ------ | -------------------------------- |
| 用户 — 行为      | 1 : N  | 一个用户产生多条行为记录         |
| 商品 — 行为      | 1 : N  | 一个商品被多条行为记录指向       |
| 用户 — 购物车    | 1 : N  | 一个用户有多个购物车条目         |
| 用户 — 订单      | 1 : N  | 一个用户有多个订单               |
| 订单 — 订单明细  | 1 : N  | 一个订单包含多个商品条目         |
| 商品 — 订单明细  | 1 : N  | 一个商品出现在多个订单明细中     |
| 类目 — 商品      | 1 : N  | 一个类目下有多个商品             |
| 类目 — 类目      | 1 : N  | 类目自关联，支持两级父子结构     |
| 用户 — 评价      | 1 : N  | 一个用户可评价多个商品           |
| 商品 — 评价      | 1 : N  | 一个商品可被多个用户评价         |

## 3. 逻辑结构设计

### 3.1 用户表 `user`

| 字段名        | 类型          | 约束                | 说明                          |
| ------------- | ------------- | ------------------- | ----------------------------- |
| `id`          | BIGINT        | PK, AUTO_INCREMENT  | 用户ID                        |
| `username`    | VARCHAR(64)   | NOT NULL, UNIQUE    | 用户名，4–20 位               |
| `password_hash`| VARCHAR(100) | NOT NULL            | BCrypt 哈希，非明文           |
| `nickname`    | VARCHAR(64)   |                     | 昵称                          |
| `email`       | VARCHAR(128)  |                     | 邮箱                          |
| `avatar`      | VARCHAR(255)  |                     | 头像 URL                      |
| `role`        | TINYINT       | NOT NULL, DEFAULT 1 | 角色：1-普通用户，2-管理员    |
| `status`      | TINYINT       | NOT NULL, DEFAULT 1 | 状态：1-正常，0-禁用          |
| `last_login_time` | DATETIME  |                     | 最后登录时间                  |
| `is_deleted`  | TINYINT       | NOT NULL, DEFAULT 0 | 逻辑删除标记                  |
| `create_time` | DATETIME      | NOT NULL            | 创建时间                      |
| `update_time` | DATETIME      | NOT NULL            | 更新时间                      |

**索引**：`UNIQUE KEY uk_username (username)`、`KEY idx_role_status (role, status)`

> **安全说明**：参考项目使用 `where bNo=? and bPassword=?` 明文比对密码。
> 本表只存 BCrypt 哈希值，字段名 `password_hash` 从命名上强制区别于明文密码。

### 3.2 类目表 `category`

| 字段名        | 类型         | 约束                | 说明                       |
| ------------- | ------------ | ------------------- | -------------------------- |
| `id`          | BIGINT       | PK, AUTO_INCREMENT  | 类目ID                     |
| `name`        | VARCHAR(64)  | NOT NULL            | 类目名称                   |
| `parent_id`   | BIGINT       | NOT NULL, DEFAULT 0 | 父级ID，0 表示一级类目     |
| `sort_order`  | INT          | NOT NULL, DEFAULT 0 | 排序值，越小越靠前         |
| `is_deleted`  | TINYINT      | NOT NULL, DEFAULT 0 | 逻辑删除标记               |
| `create_time` | DATETIME     | NOT NULL            | 创建时间                   |
| `update_time` | DATETIME     | NOT NULL            | 更新时间                   |

**索引**：`KEY idx_parent_id (parent_id)`

### 3.3 商品表 `product`

| 字段名         | 类型           | 约束                | 说明                          |
| -------------- | -------------- | ------------------- | ----------------------------- |
| `id`           | BIGINT         | PK, AUTO_INCREMENT  | 商品ID                        |
| `category_id`  | BIGINT         | NOT NULL            | 所属类目ID                    |
| `name`         | VARCHAR(200)   | NOT NULL            | 商品名称                      |
| `subtitle`     | VARCHAR(255)   |                     | 商品副标题                    |
| `main_image`   | VARCHAR(255)   |                     | 主图 URL                      |
| `price`        | DECIMAL(10,2)  | NOT NULL            | 售价                          |
| `original_price`| DECIMAL(10,2) |                     | 原价                          |
| `stock`        | INT            | NOT NULL, DEFAULT 0 | 库存，不得为负                |
| `sales`        | INT            | NOT NULL, DEFAULT 0 | 销量                          |
| `status`       | TINYINT        | NOT NULL, DEFAULT 1 | 状态：1-上架，0-下架          |
| `description`  | TEXT           |                     | 商品详情描述                  |
| `is_deleted`   | TINYINT        | NOT NULL, DEFAULT 0 | 逻辑删除标记                  |
| `create_time`  | DATETIME       | NOT NULL            | 创建时间                      |
| `update_time`  | DATETIME       | NOT NULL            | 更新时间                      |

**索引**：
- `KEY idx_category_id (category_id)` —— 类目筛选
- `KEY idx_status_sales (status, sales DESC)` —— 热门排序
- `KEY idx_name (name)` —— 关键字搜索

### 3.4 行为表 `behavior` ★推荐算法数据源

| 字段名        | 类型         | 约束                | 说明                                              |
| ------------- | ------------ | ------------------- | ------------------------------------------------- |
| `id`          | BIGINT       | PK, AUTO_INCREMENT  | 行为ID                                            |
| `user_id`     | BIGINT       | NOT NULL            | 用户ID                                            |
| `product_id`  | BIGINT       | NOT NULL            | 商品ID                                            |
| `behavior_type`| VARCHAR(16) | NOT NULL            | 行为类型：VIEW/CLICK/CART/PURCHASE/RATE           |
| `weight`      | DECIMAL(4,2) | NOT NULL            | 行为权重：1.0/2.0/3.0/5.0/4.0                     |
| `rating`      | TINYINT      |                     | 评分值 1–5，仅 RATE 类型有值                      |
| `created_at`  | DATETIME     | NOT NULL            | 行为发生时间                                      |

**索引**：
- `KEY idx_user_id (user_id)` —— UserCF 按用户取行为
- `KEY idx_product_id (product_id)` —— ItemCF 按商品取行为
- `KEY idx_created_at (created_at)` —— 时间窗口过滤（近 30 天热门）
- `KEY idx_user_product (user_id, product_id)` —— 去重查询

> **设计说明**：本表是推荐算法的输入基础，也是参考项目中**完全缺失**的部分
> ——原房屋租赁系统是纯 CRUD 管理系统，不采集任何用户行为，因而天然不具备推荐能力。

**行为类型与权重：**

| 类型       | `behavior_type` | `weight` | 触发时机           |
| ---------- | --------------- | -------- | ------------------ |
| 浏览       | `VIEW`          | 1.00     | 进入商品详情页     |
| 点击       | `CLICK`         | 2.00     | 点击推荐位/列表项  |
| 加入购物车 | `CART`          | 3.00     | 加入购物车         |
| 购买       | `PURCHASE`      | 5.00     | 订单完成           |
| 评分       | `RATE`          | 4.00     | 提交评价           |

## 4. 物理结构设计

### 4.1 建库语句

```sql
CREATE DATABASE IF NOT EXISTS recommend_db
  DEFAULT CHARACTER SET utf8mb4
  DEFAULT COLLATE utf8mb4_unicode_ci;
```

### 4.2 索引设计汇总

| 表          | 索引名            | 字段                   | 类型   | 设计目的                   |
| ----------- | ----------------- | ---------------------- | ------ | -------------------------- |
| `user`      | `uk_username`     | `username`             | UNIQUE | 用户名唯一性 + 登录查询   |
| `user`      | `idx_role_status` | `role, status`         | NORMAL | 后台按角色筛选             |
| `category`  | `idx_parent_id`   | `parent_id`            | NORMAL | 类目树查询                 |
| `product`   | `idx_category_id` | `category_id`          | NORMAL | 类目筛选商品               |
| `product`   | `idx_status_sales`| `status, sales DESC`   | NORMAL | 热门商品排序               |
| `product`   | `idx_name`        | `name`                 | NORMAL | 关键字搜索                 |
| `behavior`  | `idx_user_id`     | `user_id`              | NORMAL | UserCF 取用户行为          |
| `behavior`  | `idx_product_id`  | `product_id`           | NORMAL | ItemCF 取商品行为          |
| `behavior`  | `idx_created_at`  | `created_at`           | NORMAL | 近 30 天热门窗口           |
| `behavior`  | `idx_user_product`| `user_id, product_id`  | NORMAL | 行为去重                   |
| `cart`      | `uk_user_product` | `user_id, product_id`  | UNIQUE | 购物车条目唯一             |
| `orders`    | `uk_order_no`     | `order_no`             | UNIQUE | 订单号唯一                 |
| `orders`    | `idx_user_status` | `user_id, status`      | NORMAL | 用户订单列表与状态筛选     |
| `order_item`| `idx_order_no`    | `order_no`             | NORMAL | 订单详情查询               |
| `review`    | `uk_user_product` | `user_id, product_id`  | UNIQUE | 防重复评价                 |

### 4.3 数据完整性约束

| 约束类型 | 实现方式                                                         |
| -------- | ---------------------------------------------------------------- |
| 实体完整性 | 各表 `id` 主键自增                                              |
| 参照完整性 | 应用层保证（外键在 Service 层校验），数据库层不建外键以降低耦合 |
| 域完整性   | 金额 `DECIMAL(10,2)`；评分 `TINYINT` + 应用层 1–5 校验           |
| 用户自定义 | 库存不得为负：更新时使用 `WHERE stock >= #{quantity}` 条件更新防超卖 |

> **说明**：不采用数据库外键是互联网项目的常见取舍——外键会带来级联锁与
> 分库分表障碍，改为在 Service 层做存在性校验。逻辑删除标记 `is_deleted`
> 保证历史订单的可追溯性。

## 5. 数据初始化方案

### 5.1 初始化流程

```
1. 执行 sql/schema.sql         → 建库建表
2. 执行 sql/seed/seed_data.sql → 导入种子数据
   （由 tools/seed-generator 生成，固定随机种子保证可复现）
```

### 5.2 种子数据规模

| 数据       | 规模     | 生成方式                                             |
| ---------- | -------- | ---------------------------------------------------- |
| 用户       | 200      | 生成 `user001`–`user200`，默认密码统一哈希           |
| 类目       | 10 一级 / 30 二级 | 手工预置                                   |
| 商品       | 500      | 按类目分配，价格区间 9.9–4999                       |
| 行为记录   | ≥ 5000   | 按用户兴趣偏好分布生成，保证有足够共现               |
| 订单       | ≥ 800    | 由 PURCHASE 行为派生                                 |
| 评价       | ≥ 600    | 由 RATE 行为派生                                     |

### 5.3 可复现性保证

种子生成器使用**固定随机种子**（`Random(20261027)`），
保证任何人、任何时间生成的演示数据完全一致，
便于算法评测结果复现与答辩演示。

### 5.4 默认账号

| 角色   | 用户名    | 密码      | 说明                     |
| ------ | --------- | --------- | ------------------------ |
| 管理员 | `admin`   | `admin123`| 后台管理入口             |
| 普通用户 | `user001` | `123456` | 用于演示个性化推荐效果   |

> 种子数据中的密码同样以 BCrypt 哈希写入，上表仅为明文提示。

## 6. 与参考项目的对比改进

| 维度         | 参考项目（`houselease`）                    | 本项目（`recommend_db`）                    |
| ------------ | ------------------------------------------- | ------------------------------------------- |
| 密码字段     | `bPassword` 明文存储                        | `password_hash` BCrypt 哈希                 |
| 日期字段     | `String mWorkDate` 字符串存日期             | `DATETIME` 原生时间类型                     |
| 主键         | 业务字符串编号（如 `aNo`）                  | `BIGINT` 自增 ID + 业务唯一索引             |
| 行为数据     | 无                                          | `behavior` 表，含类型与权重，供算法使用     |
| 逻辑删除     | 物理 `DELETE`                               | `is_deleted` 逻辑删除，保留可追溯性         |
| 审计字段     | 无                                          | 全表含 `create_time` / `update_time`        |
| 索引         | 仅主键                                       | 15 个针对性索引，覆盖算法与列表查询         |
| 金额精度     | 无金额字段                                  | `DECIMAL(10,2)`，避免浮点误差               |
| 快照冗余     | 无                                          | 订单明细冗余商品名与价格快照                |
| 初始化脚本   | 无（手工建表）                              | `schema.sql` + 种子脚本，一键初始化         |
