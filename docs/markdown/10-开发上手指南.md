## 一、IDEA 环境配置（按顺序做）

### 1. 打开项目

`File → Open` → 选 `D:\桌面\商品推荐系统` → `OK`。
IDEA 会自动识别 `recommend-server/pom.xml`，右下角弹窗选 **Load Maven Project**。

### 2. 配置 JDK 17（本机已有 `D:\java17`，版本 17.0.5）

```
File → Project Structure (Ctrl+Alt+Shift+S)
  ├── Project
  │     ├── SDK        : 点 Add SDK → Add JDK → 选 D:\java17
  │     └── Language level : 17 - Sealed types...
  └── Modules → recommend-server → Language level : 17
```

> ⚠️ 本机 `JAVA_HOME` 环境变量指向 `D:\java8`，**不要改它**（可能影响其他项目），
> 只在 IDEA 里指定 JDK 17 即可。命令行构建时用 `JAVA_HOME=D:/java17 ./mvnw`。

### 3. 配置 Maven（关键）

```
Settings (Ctrl+Alt+S) → Build, Execution, Deployment → Build Tools → Maven
  ├── Maven home path      : 选 "Use Maven wrapper"  ← 推荐
  │                          （或手填 D:\tools\apache-maven-3.9.16）
  ├── User settings file   : C:\Users\邓董\.m2\settings.xml   （已配好阿里云镜像）
  ├── Local repository     : D:\maven-repo   ← 已改到 D 盘，见下方说明
  └── Runner → JRE         : 17
```

> **本地仓库为什么在 D 盘而不是默认的 `C:\Users\邓董\.m2\repository`**
> 1. C 盘当时已用 94%（仅剩 7.9G），而 Maven 仓库会持续膨胀到数百 MB
> 2. 中文用户名路径在个别 Maven 插件/工具下存在编码风险（同 ssh 那个坑）
>
> 配置写在 `settings.xml` 的 `<localRepository>D:/maven-repo</localRepository>`。
> **IDEA 里的 "Local repository" 如果填了旧路径会覆盖 settings.xml**——
> 要么清空让它跟随 settings.xml，要么手动填成 `D:\maven-repo`。

别忘了给 IDEA 的运行配置也指定 JDK 17：

```
Settings → Build Tools → Maven → Runner → JRE : 选 17
```

### 4. 编码统一 UTF-8（不做会出现中文乱码）

```
Settings → Editor → File Encodings
  ├── Global Encoding      : UTF-8
  ├── Project Encoding     : UTF-8
  ├── Default encoding for properties files : UTF-8
  └── ☑ Transparent native-to-ascii conversion
```

### 5. 开启注解处理（Lombok 必须开）

```
Settings → Build, Execution, Deployment → Compiler → Annotation Processors
  └── ☑ Enable annotation processing
```

然后安装插件：`Settings → Plugins` 搜 **Lombok** 安装并重启。
（可选但推荐：装 **MyBatisX**，Mapper 与 XML 之间可以互相跳转。）

### 6. 数据库准备

```bash
# 命令行执行（MySQL 8.0.27 在 D:\mysql\mysql-8.0.27-winx64\bin）
# 必须带 --default-character-set=utf8mb4，否则所有中文表注释会变乱码
mysql --default-character-set=utf8mb4 -u root -p
```

```sql
source D:/桌面/商品推荐系统/sql/schema.sql;
```

> ⚠️ **这是最容易踩的一个坑**：Windows 下 mysql 客户端默认按 GBK 解析脚本，
> 而 `schema.sql` 是 UTF-8。不加字符集参数时表能建出来，但中文注释会变成
> 「鏀惰棌ID」这种乱码。已经乱了就把表 DROP 掉，带上参数重跑一次。

或在 IDEA 里：`Database` 面板 → `+` → `Data Source` → `MySQL`，
填 host `localhost`、port `3306`、user `root`，**密码不要存进 IDEA 的 datasource 配置里提交到 Git**。

### 7. 数据库口令不要写进配置文件

`application.yml` 里已经改成从环境变量读：

```yaml
username: ${DB_USERNAME:root}
password: ${DB_PASSWORD:}
```

在 IDEA 里给启动类配环境变量：

```
Run → Edit Configurations → RecommendApplication
  └── Environment variables : DB_USERNAME=root;DB_PASSWORD=你的密码;JWT_SECRET=至少32位随机串
```

> 这一步是硬要求。参考项目把 MySQL 的 root 口令明文写在 `application.properties` 里，
> 一旦推到公开仓库就等于把数据库交出去了（**本文档刻意不写出那个口令**）。

### 8. 验证环境

在 IDEA 右侧 **Maven** 面板展开 `recommend-server → Lifecycle`，双击 `compile`。
看到 `BUILD SUCCESS` 即环境 OK。
（若控制台中文乱码，去 `Settings → Editor → General → Console` 把编码设为 UTF-8。）

## 二、建包顺序与文件命名清单

在 `recommend-server/src/main/java/com/deng/recommend` 下依次建包。
**建议按下面的顺序建**，因为后者依赖前者。

### 第 1 步：`entity/enums` —— 先定义枚举，后面所有层都要用

| 文件名              | 内容                                                    |
| ------------------- | ------------------------------------------------------- |
| `UserRole.java`     | `USER(1,"普通用户")`、`ADMIN(2,"管理员")`，含 `of(Integer)` |
| `BehaviorType.java` | `VIEW(1.0)`、`CLICK(2.0)`、`CART(3.0)`、`PURCHASE(5.0)`、`RATE(4.0)` |
| `OrderStatus.java`  | `PENDING(0)`…`CANCELLED(4)`，含 `cancellable()`          |

> **命名规范**：枚举类名大驼峰，枚举常量全大写，必须是名词或状态词。

### 第 2 步：`entity` —— 一张表一个实体，类名 = 表名单数大驼峰

| 文件名          | 对应表       | 要点                                              |
| --------------- | ------------ | ------------------------------------------------- |
| `User.java`     | `user`       | 字段叫 `passwordHash` **不叫** password，警示勿存明文 |
| `Category.java` | `category`   | `parentId` 为 0 表示一级类目                       |
| `Product.java`  | `product`    | 金额用 `BigDecimal`，库存 `Integer`                |
| `Behavior.java` | `behavior`   | 含 `applyType(BehaviorType)` 自动填权重            |
| `Cart.java`     | `cart`       | 唯一键 `(user_id, product_id)`                     |
| `Order.java`    | `orders`     | 表名避开 MySQL 关键字 `order`                      |
| `OrderItem.java`| `order_item` | 冗余 `productName` / `price` 快照                  |
| `Review.java`   | `review`     | 唯一键 `(user_id, product_id)`                     |

### 第 3 步：`common` —— 统一响应与异常，所有接口都依赖

| 文件名                       | 作用                                     |
| ---------------------------- | ---------------------------------------- |
| `ResultCode.java`            | 错误码枚举，分段：1xxx通用/2xxx用户/3xxx商品/4xxx交易/5xxx推荐/9xxx系统 |
| `Result.java`                | 统一响应体 `Result<T>`，含 `success()/fail()` 静态工厂 |
| `BusinessException.java`     | 业务异常，带错误码                       |
| `GlobalExceptionHandler.java`| `@RestControllerAdvice` 全局兜底，永不把堆栈给前端 |
| `PageResult.java`            | 分页响应封装，含 `PageResult.of(IPage)`   |

### 第 4 步：`config` —— 配置类

| 文件名                   | 作用                                             |
| ------------------------ | ------------------------------------------------ |
| `MybatisPlusConfig.java` | 分页插件 + `createTime/updateTime` 自动填充       |
| `CorsConfig.java`        | 跨域，允许前端 5173 端口                          |
| `OpenApiConfig.java`     | Swagger 文档元信息                                |
| `RecommendProperties.java` | 推荐参数（K、N、权重）从 yml 读，**禁止写死在算法里** |
| `SecurityConfig.java`    | Spring Security：JWT 无状态、URL 权限、`BCryptPasswordEncoder` |
| `SecurityUtils.java`     | 取当前登录用户 ID，用于越权防护                   |

### 第 5 步：`security` —— JWT 鉴权

| 文件名                        | 作用                                    |
| ----------------------------- | --------------------------------------- |
| `UserPrincipal.java`          | 实现 `UserDetails`，承载 userId/role     |
| `JwtTokenProvider.java`       | 签发、校验、解析令牌（密钥 ≥ 32 字节）   |
| `JwtAuthenticationFilter.java`| 解析 `Authorization: Bearer xxx`         |

### 第 6 步：`mapper` —— 一张表一个 Mapper，接口名 = 实体名 + Mapper

`UserMapper` / `CategoryMapper` / `ProductMapper` / `BehaviorMapper` /
`CartMapper` / `OrderMapper` / `OrderItemMapper` / `ReviewMapper`

均继承 `BaseMapper<实体>`，不加 `@Mapper` 也行（启动类上有 `@MapperScan`），但加上更明确。
`BehaviorMapper` 额外写一个 `selectBehaviorRecords(since, limit)` 用于构建推荐矩阵。

### 第 7 步：`recommend` —— 推荐引擎（本项目核心，与业务解耦）

```
recommend/
├── RecommendStrategy.java        策略接口：recommend(matrix, request)
├── UserCFStrategy.java           基于用户的协同过滤
├── ItemCFStrategy.java           基于物品的协同过滤
├── HotFallbackStrategy.java      热门兜底（冷启动）
├── HybridStrategy.java           混合推荐（归一化后加权）
├── RecommendEngine.java          门面：路由 + 补全 + 异常降级
├── similarity/CosineSimilarity.java   余弦相似度（含热门惩罚）
├── model/UserItemMatrix.java     用户-物品矩阵（正向 + 倒排索引）
├── model/BehaviorRecord.java     算法输入单元，与数据库实体解耦
├── model/ScoredItem.java         算法输出单元（商品ID + 推荐分 + 理由）
├── model/RecommendRequest.java   推荐请求上下文
└── evaluator/RecommendEvaluator.java  离线评测 Precision/Recall/F1/Coverage
```

> **设计要点**：算法层的输入是 `UserItemMatrix`，不是数据库连接。
> 这样算法可以脱离数据库单测——参考项目的 `CoreMath` 就是因为耦合了 DB 才没法测。

### 第 8 步：`dto` / `vo` —— 入参与出参

| dto（请求体，类名 = 动作 + Request）        | vo（响应体，类名 = 实体 + VO） |
| ------------------------------------------ | ------------------------------ |
| `LoginRequest` / `RegisterRequest`          | `UserVO`                       |
| `ProductQuery`（列表查询条件）              | `ProductVO` / `CategoryVO`     |
| `BehaviorReportRequest`                     | `RecommendVO`（含 score+reason）|
| `CartAddRequest` / `CartUpdateRequest`      | `CartVO`                       |
| `OrderCreateRequest`                        | `OrderVO` / `OrderItemVO`      |
| `ReviewRequest`                             | `ReviewVO`                     |

> 规则：**Entity 永不直接返回给前端**，一律转 VO。
> 校验注解（`@NotBlank`、`@Size`、`@Min`）写在 DTO 上，不写在 Entity 上。

### 第 9 步：`service` —— 接口放 `service/`，实现放 `service/impl/`

| 接口                 | 实现类                  | 核心方法                                        |
| -------------------- | ----------------------- | ----------------------------------------------- |
| `AuthService`        | `AuthServiceImpl`       | `register` / `login`                            |
| `ProductService`     | `ProductServiceImpl`    | `page` / `detail`                               |
| `CategoryService`    | `CategoryServiceImpl`   | `tree`                                          |
| `BehaviorService`    | `BehaviorServiceImpl`   | `report` / `buildMatrix`                        |
| `RecommendService`   | `RecommendServiceImpl`  | `recommendForUser` / `recommendSimilar` / `recommendHot` / `recommendHybrid` / `evaluate` |
| `CartService`        | `CartServiceImpl`       | `add` / `list` / `update` / `remove`            |
| `OrderService`       | `OrderServiceImpl`      | `create`（事务）/ `page` / `detail` / `cancel`  |
| `ReviewService`      | `ReviewServiceImpl`     | `submit` / `pageByProduct`                      |
| `AdminService`       | `AdminServiceImpl`      | `saveProduct` / `statistics`                    |

**命名规范**：接口 `XxxService`，实现 `XxxServiceImpl`，实现类加
`@Service` + `@RequiredArgsConstructor` + `@Slf4j`，**只用构造器注入，不许用 `@Autowired` 字段注入**。

### 第 10 步：`controller` —— 一个资源一个 Controller

`AuthController` / `ProductController` / `CategoryController` /
`BehaviorController` / `RecommendController` / `CartController` /
`OrderController` / `ReviewController` / `admin/AdminController`

规则：`@RestController` + `@RequestMapping("/api/xxx")`；**Controller 里不许写业务逻辑**，
只做三件事——收参数、调 Service、包 `Result.success(data)`。

### 第 11 步：资源文件

| 路径                                              | 内容                        |
| ------------------------------------------------- | --------------------------- |
| `src/main/resources/application.yml`              | 数据源、JWT、推荐参数（口令走环境变量） |
| `src/main/java/.../RecommendApplication.java`     | 启动类，加 `@MapperScan`     |
| `../../sql/schema.sql`（仓库根 `sql/`）            | 建表脚本                    |
| `../../sql/seed/`                                 | 种子数据脚本                |

## 四、最容易踩的坑（都是参考项目踩过的）

| # | 坑                                                        | 怎么避免                                                     |
| - | --------------------------------------------------------- | ------------------------------------------------------------ |
| 1 | 拿 `Map.values()` 当"相似度最高的邻居"                     | 排序时必须按**相似度**排，写完立刻写单测断言邻居 ID            |
| 2 | 用 `Math.random()` 伪造行为强度                            | 建真实 `behavior` 表，按行为类型给确定权重                     |
| 3 | 皮尔森相关系数在 `n=0` 时返回 `NaN`，且 `NaN==0` 为 false  | 改用余弦相似度；或至少先判 `if (n == 0) return 0.0;`           |
| 4 | 结果按商品 ID 排序，不是按推荐分                           | 给每个候选商品算分，`ScoredItem` 实现 `Comparable` 按分降序    |
| 5 | 冷启动时 `userMap.get(userId)` 为 null → NPE               | 无行为直接走热门兜底，引擎层 try-catch 兜住                    |
| 6 | 相似度写死 K=3                                             | 放 `application.yml` 的 `recommend.neighbor-k`                |
| 7 | 测试写在 `src/main/test/`                                  | 必须放 `src/test/java`，否则 Maven 不执行                      |
| 8 | 密码用无加盐 MD5                                           | `BCryptPasswordEncoder`                                       |
| 9 | 数据库口令写进配置文件推到 GitHub                          | 走环境变量 + `.env.example`                                   |
| 10| SQL 字符串拼接                                             | MyBatis-Plus 条件构造器，或 XML 里用 `#{}` 绝不用 `${}`         |
| 11| 下单超卖                                                   | 扣库存用 `ge(Product::getStock, qty)` 条件更新 + `@Transactional` |
| 12| 越权：传个别人的 orderNo 就能查到订单                       | 每个查询强制拼 `userId` 过滤                                   |

## 七、Git 提交规范与 GitHub 推送

### 7.1 哪些东西绝不能提交

`.gitignore` 已经屏蔽了下面这些，但你要知道屏蔽了什么：

| 类别           | 具体                                              | 为什么                         |
| -------------- | ------------------------------------------------- | ------------------------------ |
| 构建产物       | `target/`、`.class`、`*.jar`                       | 体积大、每次编译都变           |
| IDE 配置       | `.idea/`、`*.iml`、`.vscode/`                      | 每人环境不同，会冲突           |
| 前端依赖       | `node_modules/`、`dist/`、`.vite/`                 | 几万个小文件，`npm install` 可重建 |
| **密钥口令**   | `.env`、`*local.yml`、`application-secret.yml`、`*.pem` | **提交了就是泄露，必须换密钥** |
| 数据库快照     | `*_dump.sql`、`*_backup.sql`                       | 体积大，且可能含真实数据       |
| 日志           | `logs/`、`*.log`                                   | 无意义且增长快                 |

**本项目已经做对的两件事**（参考项目都没做）：

1. `application.yml` 里数据库口令是 `${DB_PASSWORD:}`，从环境变量读，**配置文件本身不含任何口令**。
2. 仓库里有 `.env.example`（模板，入库），你本地复制成 `.env` 填真口令（不入库）。

```bash
cp .env.example .env      # .env 已被 .gitignore 屏蔽
```

### 7.2 别用 `git add -A` 一股脑提交

正确流程——**先看，再挑，再提交**：

```bash
# 1. 看看改了什么（这一步不能省）
git status

# 2. 逐类检查有没有夹带不该提交的文件
git status --short          # 简短列表
git diff --stat             # 改了多少行

# 3. 只加你要提交的文件（用明确路径，不要用 -A）
git add docs/markdown/02-需求规格说明书.md
git add recommend-server/src/main/java/com/deng/recommend/recommend/

# 4. 提交前最后确认一遍将要入库的内容
git diff --cached --stat

# 5. 提交
git commit -m "feat(recsys): 实现 UserCF 相似度计算与 Top-K 邻居选取"
```

**万一已经误提交了密钥**，立刻做两件事：
① 去 GitHub / 数据库把那个口令**作废换掉**（删提交历史没用，已经被爬走了）；
② `git rm --cached <文件>` 把它移出版本控制，再加进 `.gitignore`。

### 7.3 提交粒度（对应第三章的 10 个阶段）

- 一个阶段 = 一个 commit，**不要**攒几十个文件一次提交。
- commit message 用 Conventional Commits：

| 前缀       | 什么时候用                       |
| ---------- | -------------------------------- |
| `feat`     | 新功能                           |
| `fix`      | 修 bug                           |
| `test`     | 只加/改测试                      |
| `docs`     | 只改文档                         |
| `refactor` | 重构，行为不变                   |
| `chore`    | 构建、依赖、配置                 |

```bash

```

### 7.6 私有仓库注意事项（本仓库为 Private）

| 事项             | 说明                                                                 |
| ---------------- | -------------------------------------------------------------------- |
| 可见性           | 只有你和被邀请的协作者能看到，不会被搜索引擎/爬虫抓取                 |
| **想让别人看到** | 私有仓库别人看不到。要么 `Settings → Danger Zone → Change visibility` 转 Public，要么 `Settings → Collaborators` 邀请协作者 |
| Actions 配额     | 免费账户私有仓库每月 2000 分钟（公开仓库无限），加 CI 时注意用量       |
| GitHub Pages     | 免费账户的私有仓库**不支持** Pages。想部署在线演示要转公开或用其他托管 |
| 令牌/密钥        | 私有也不代表绝对安全，**口令依然不能提交**（换电脑、借账号、误转公开都会泄露） |

> 转 Public 之前务必再跑一遍 7.5 的自检，确认历史里没有任何口令。
